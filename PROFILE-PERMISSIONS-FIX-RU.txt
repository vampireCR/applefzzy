ИСПРАВЛЕНИЕ: permission denied for table profiles

Причина:
Сайт сохраняет поля профиля в public.profiles (bio, status, interest, app_data), но у роли authenticated не было необходимых SQL UPDATE-привилегий. Политика RLS сама по себе не выдаёт SQL-привилегии — нужны и GRANT, и подходящая RLS policy.

ЧТО ДЕЛАТЬ:
1. Открой Supabase -> SQL Editor -> New query.
2. Открой profiles-permissions-fix.sql из этого архива.
3. Скопируй весь SQL, вставь в редактор и нажми Run.
4. Убедись, что запрос завершился без ошибки.
5. Загрузи в корень GitHub Pages index.html и cloud.js из этого архива (а также остальные файлы, если они отличаются от текущей версии).
6. Дождись успешной публикации, затем открой сайт через Ctrl+F5 и войди заново.

Что именно разрешается:
- authenticated может читать профили (для каталога и открытия чужих профилей);
- пользователь может обновлять только собственную строку profiles;
- UPDATE разрешён только для bio, status, interest и app_data;
- роль, username, handle и служебные поля не открываются для обычного обновления.

Политика не разрешает менять чужие профили. Существующие данные не удаляются.

Если ошибка останется:
- открой F12 -> Console;
- скопируй полную ошибку, особенно code/details/hint;
- не публикуй SERVICE_ROLE_KEY и другие секреты.
