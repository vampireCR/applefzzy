   «Ты не один», «Обнимаю» и прочие кнопки поддержки из ленты.

   Убрано поле «Отношения» из редактирования и публичного блока профиля.
   Платформа позиционируется как городское и школьное сообщество, а не сервис знакомств.
5. В групповых и канальных чатах добавлена отправка изображений и файлов до 20 МБ.
   Для них используется закрытый Supabase Storage bucket и подписанные ссылки.
6. В настройках добавлен выбор акцентного цвета интерфейса и языка:
   русский, украинский, английский. Правила Apple Book теперь опубликованы
   на всех трёх языках.

ВАЖНО О ЯЗЫКАХ И ФАЙЛАХ
-----------------------
Переключатель языка и словарь переводят основные элементы навигации, новые
разделы и распространённые подписи старого интерфейса. Это ещё не полная
профессиональная локализация каждой старой административной формы и каждого
уведомления: такие остаточные английские строки нужно будет последовательно
добавить в словарь. Правила полностью представлены на русском, украинском
и английском.

Вложения в этой версии работают в группах и каналах. В личных переписках
старого модуля отправка файлов пока не подключена. Не называй её готовой.
Голосовые сообщения, звонки и видеозвонки также требуют отдельной реализации.

КАК УСТАНОВИТЬ
--------------
1. Сохрани копию текущего репозитория.
2. Распакуй архив и загрузи все файлы из него в корень GitHub Pages-репозитория,
   рядом с index.html. Не создавай дополнительную вложенную папку.
3. Не удаляй таблицы Supabase и не очищай данные пользователей.
4. Открой Supabase → SQL Editor и выполни обновлённый APPLEBOOK-UPGRADE.sql целиком.
   Скрипт добавляет поля вложений, закрытое хранилище и политики доступа; существующие
   профили, личные сообщения, дружбы и контент не удаляются. Его можно безопасно
   выполнить повторно: новые политики и ограничения предварительно проверяются.
5. Дождись успешного выполнения SQL и публикации GitHub Pages.
6. Открой сайт и сделай Ctrl+F5. Войди в существующий аккаунт.
7. В «Люди по интересам» заполни интересы, школу и город/район и нажми «Сохранить».
   Затем проверь поиск по интересу и школе.
8. Проверь отправку обычного сообщения и файла в тестовой группе.

ИСПРАВЛЕНИЕ «RESET PASSWORD» И «DELETE ACCOUNT» (ВАЖНО)
------------------------------------------------------
Причина ошибки: браузер вызывает Supabase Edge Function applebook-admin, но
сообщение «Failed to send a request to the Edge Function» означает, что функция
не развёрнута в проекте или недоступна. Бан и верификация работают через SQL RPC,
поэтому они не зависят от этой Edge Function.

В архив добавлена готовая функция:
  supabase/functions/applebook-admin/index.ts
  supabase/config.toml

ОДИН РАЗ разверни её в том же Supabase-проекте. SQL для этого не нужен.
Установи Supabase CLI, открой PowerShell в папке проекта (там, где лежит папка
supabase), затем выполни:

  supabase login
  supabase link --project-ref tzkxujrjrhyqxgzytaex
  supabase functions deploy applebook-admin

Если CLI спросит database password, введи пароль проекта Supabase. Не вставляй
service_role key в index.html, cloud.js, GitHub или сообщения. Функция использует
серверный SUPABASE_SERVICE_ROLE_KEY из окружения Supabase; он не попадает в браузер.

После успешного deploy обнови сайт через Ctrl+F5 и проверь:
1. Сброс пароля другого пользователя с более низким рангом. Функция создаёт
   одноразовую ссылку восстановления и показывает её для копирования/передачи.
2. Удаление тестового аккаунта с более низким рангом.
3. Самостоятельное удаление обычного аккаунта (владелец защищён).

ПРАВА И ОГРАНИЧЕНИЯ
- Только CEO/Deputy CEO/Owner могут сбрасывать пароль или удалять чужие аккаунты.
- Нельзя управлять аккаунтами равного или более высокого ранга.
- Удаление своего обычного аккаунта разрешено; аккаунт Owner защищён.
- Проверка токена выполняется на сервере; роль и цель операции повторно проверяются
  по таблице profiles. Клиентский код не получает service_role key.
- Для проверки сначала используй тестовый аккаунт. Удаление Auth-пользователя
  необратимо и может затронуть связанные данные в зависимости от FK-ограничений.

Никакой дополнительный SQL запускать для этой Edge Function не требуется.
Если после deploy появится новая ошибка, открой Supabase → Edge Functions →
applebook-admin → Logs и пришли текст ошибки.

APPLE BOOK V6 — исправление чата и обновление оформления
========================================================

Что изменено в V6:
- Убрана лишняя старая кнопка «Отправить»: в чате остаётся одна кнопка отправки.
- Исправлена причина, по которой текстовое сообщение не доходило до Supabase: поле ввода снова имеет ID mt, который использует cloud.js.
- Фото и документы отправляются через один корректно подключённый input ab-upload-input; после отправки можно выбирать следующий файл.
- Меню скрепки открывается компактно рядом с полем сообщения, с плавной анимацией, а не занимает половину экрана.
- Удалён пункт «Перевод» из меню.
- Верхний бренд использует 3D-логотип надкусанного яблока; обновлены меню, правые кнопки и баннер.
- В настройках добавлены отдельные цвета фона страницы, карточек и верхней шапки. Эти три цвета хранятся локально на устройстве; акцентный цвет и остальные прежние параметры работают как раньше.
- В настройках показывается тип текущего устройства, платформа и браузер. Точная геолокация не запрашивается и не собирается.

Установка:
1. Распакуй ZIP.
2. Замени файлы в корне репозитория GitHub файлами из этого архива. Не удаляй существующие SQL-таблицы и данные.
3. Убедись, что скрытая папка .github/workflows тоже загружена.
4. Дождись публикации GitHub Pages. На телефоне закрой приложение полностью и открой снова; если старый интерфейс остался, очисти данные сайта/кэш браузера.
5. Для APK снова запусти Actions → Build Apple Book APK → Run workflow и скачай новый artifact.

SQL для этой версии повторно запускать не требуется, если предыдущий V5 SQL для message-files уже был успешно выполнен. Edge Function applebook-admin повторно разворачивать не нужно.

Ограничения, которые нельзя честно включить одной заменой HTML/JS:
- Push-уведомления в Android APK требуют Firebase Cloud Messaging: Android Firebase-проекта, google-services.json, серверной отправки FCM и разрешения уведомлений. В этой версии это не имитируется.
- Реальные голосовые/видеозвонки требуют WebRTC-сигналинга и TURN-сервера. Кнопки без этих компонентов не смогут надёжно соединять пользователей; звонки не объявляются работающими.
- Для списка всех активных сеансов и определения местоположения нужна отдельная серверная схема. Точная геолокация не собирается скрытно.
